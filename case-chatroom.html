Chapter 1

The journey.

Scroll to follow one message. Turn Redis off to see what breaks.

A simulation of the design. Members B and C are held by a different worker than you.

Authenticated sockets

Browsers cannot attach headers to a WebSocket, so the JWT travels with the connection and is checked before it is accepted.

Fan-out through Redis

Two people in one room can be held by different server processes. Redis pub/sub delivers each message to all of them.

What I would change

Swap the query-string token for a one-time ticket, add a catch-up step on reconnect, and rate limit every connection.

Chapter 3

What I would change.

Honest list, in the order I would do it.

  1. One-time ticket instead of a query-string tokenTokens in URLs end up in logs. A short-lived ticket fixes that.
  2. Catch-up on reconnectAsk the server for everything after the last message the client saw.
  3. Rate limit every connectionOne noisy client should not be able to slow a room down.
